## 0. 배경 · 위치

운영(momo) 첫 배포 뒤 사용해 보며 나온 수정사항이다.
- 면접관이 질문에 괄호를 쓴다("기술(파이썬, 자바)") — 실제 면접 말투와 다르다.
- 면접관이 진행 규칙을 입 밖에 낸다("꼬리 질문 3개를 다 사용했으므로 다음 질문으로 넘어갑니다"). 진행 규칙 3번의 "면접 전체에서 꼬리질문은 모두 합쳐 최대 3개입니다"를 그대로 말한 것으로 보인다. 지금 5번 규칙은 "질문 번호나 남은 질문 수"만 막는다.
- 비밀번호는 8자 이상만 검사한다("12345678" 허용).
- 가입 화면은 저장 안내 문장만 보여 주고 `consent: true`를 자동으로 보낸다. 사용자가 직접 동의하지 않는다.

## 1. 목표 · 비목표

### 목표
- 면접관(벤·로컬 3명)이 괄호와 진행·시스템 멘트를 쓰지 않는다.
- 새 가입은 8~64자·영문과 숫자 모두 포함·공백 없는 비밀번호만 받는다.
- 새 가입은 이용약관·개인정보 수집·이용에 각각 직접 동의하고, 서버는 동의한 약관 버전·시각을 저장한다.

### 비목표
- 기존 계정의 비밀번호 재설정 강제, 기존 계정의 약관 재동의
- 선택 동의(마케팅 등), 회원 탈퇴 기능
- 아이디 체계 변경(아이디는 지금처럼 이메일)

## 2. 면접관 진행 규칙 (`backend/app/llm/prompts.py`, 계층 규율 경로)

벤의 `_rules()`와 로컬 면접관(`frontend/src/prompts/interviewer.ts`)은 같은 진행 규칙을 쓴다. 두 곳 모두 아래처럼 바꾼다(로컬은 프론트 이슈).

| 규칙 | 전 | 후 |
|---|---|---|
| 1 | 한국어 존댓말을 씁니다. 한 번에 질문을 하나만 합니다. 질문은 두 문장 이내로 짧게 합니다. | (전 문장 뒤에) 괄호를 쓰지 않습니다. 예시가 필요하면 '파이썬이나 자바 같은'처럼 말로 풀어 씁니다. |
| 5 | 질문 번호나 남은 질문 수를 말하지 않습니다. | 질문 번호, 남은 질문 수, 꼬리질문 횟수, 다음 질문으로 넘어간다는 안내처럼 진행 규칙이나 시스템에 관한 말은 하지 않습니다. 실제 면접관처럼 자연스럽게 다음 질문을 합니다. |

- 종료 문장·리포트 지시문은 바꾸지 않는다(`tests/test_prompt_parity.py` 그대로 통과).
- 확인: PR에 전후 비교, demomo에서 벤·로컬 면접관 각 1회 완주.

## 3. 비밀번호 규칙 (`POST /api/auth/signup`)

- 8~64자, 영문(A–Z·a–z) 1자 이상과 숫자 1자 이상 포함, 공백 문자 없음. 특수문자는 허용(필수 아님).
- 위반 → `422 {"error":"weak_password","field":"password","rule":…}`. `rule`은 검사 순서대로 첫 위반 하나: `length`(8자 미만 또는 64자 초과) → `whitespace` → `letter_digit`.
- 가입에만 적용. 로그인·기존 계정은 그대로.
- 즉시 적용(설정 없음). 예전 화면도 `weak_password`를 이미 처리하므로 가입이 막히지는 않는다(안내 문구만 예전 그대로).

## 4. 약관 동의

### 4.1 계약 (`docs/API.md`, additive)
- 가입 요청에 `termsAgreed: boolean`(기본 false) 추가. 기존 `consent`는 "개인정보 수집·이용 동의"를 뜻한다(필수, 지금과 같음).
- 설정 `SIGNUP_TERMS_REQUIRED`(기본 `false`). 켜져 있으면 `termsAgreed`가 true가 아닐 때 `422 {"error":"terms_required","field":"termsAgreed"}`. 검사 순서: 이메일 → 비밀번호 → 이름 → `consent` → `termsAgreed` → (켜졌으면) PIN → 이메일 중복.
- `termsAgreed`가 true면(설정과 무관) 계정에 `terms_version`(현재 약관 버전 `TERMS_VERSION = "2026-10-28"`)과 `terms_agreed_at`을 저장한다.
- `GET /api/auth/signup/config` 응답에 `termsVersion: "2026-10-28"`, `termsRequired: boolean` 추가.

### 4.2 저장
- 마이그레이션 `009_terms_agreement.sql`: `users.terms_version TEXT`, `users.terms_agreed_at TEXT`(둘 다 NULL 허용). 기존 계정은 NULL.
- 응답 `Session`은 바꾸지 않는다.

### 4.3 약관 본문
- `docs/terms/2026-10-28-terms.md`(이용약관·개인정보 수집·이용 간략판). 화면은 이 내용을 [보기]로 보여 준다. 버전을 올리면 파일을 새로 만들고 `TERMS_VERSION`을 바꾼다.

### 4.4 롤아웃
백엔드 PR(꺼진 채) → dev → 프론트 가입 화면 → demomo `.env`에서 `SIGNUP_TERMS_REQUIRED=true` → 가입 1회 확인 → 운영.
