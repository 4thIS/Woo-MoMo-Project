# 리포트 레이아웃 — 길이를 줄이지 말고 훑을 수 있게 (spec)

- 생성일시: 2026-11-07
- 수정일시: 2026-11-07

## 0. 배경 · 위치

전체 설계서 6절 "리포트 화면"에 해당한다. `2026-09-16-report-print-timing-autosend-design.md`(인쇄·시간)와 벤 리포트 v2(`2026-10-30` 백엔드 spec의 프론트 짝)의 뒤를 잇는다.

개편 시안(승인 완료): https://claude.ai/artifact/7q3VdUDuQdVcgpyKHdWLVd — 아트보드 `리포트 A — 왼쪽 요약 레일`, `리포트 — 문항 카드 속`, `긴 리포트 — 문항 16개일 때`, `긴 리포트 — 읽기 규칙`

개편 순서에서 **4번**. 선행: 스크롤 애니메이션 철거, 모던 레트로 껍데기.

### 지금 무엇이 문제인가

| 현상 | 원인 |
|---|---|
| 같은 버튼 셋이 위아래로 **두 번** 나온다 | 화면이 길어서 생긴 땜질(`.btns`와 `.btns.bottom`) |
| "시간" 창이 리포트 본문보다 **먼저** 온다 | 문항별 초과 시간 목록이 머리에 있다. "무엇을 고칠지"보다 위다 |
| 문항이 일곱 장을 넘으면 훑을 방법이 없다 | 목차가 없다. 전부 스크롤해야 한다 |
| 벤 카드마다 **열 줄짜리 표**가 붙는다 | 측정값 5줄 + 목소리 5줄이 늘 펼쳐져 있다. 일곱 번 반복되면 피드백보다 측정값이 길다 |
| 라벨이 본문 폭을 먹는다 | `ReportCards`가 `dt`/`dd` 가로 배치다. 줄간 1.45로 빡빡하다 |

벤 면접은 본질문 10 + 꼬리질문 6까지 나올 수 있다. 그 분량에서 끝까지 읽히게 만드는 것이 이 spec의 과제다.

## 1. 목표 · 비목표

### 목표

- 결론(총평)과 목차를 **늘 보이는 자리**에 두어, 문항이 열여섯이어도 길을 잃지 않게 한다.
- 긴 답변과 피드백을 읽기 좋게 만든다 — 줄 길이 · 줄간 · 여백 위계.
- 측정값을 접되, **고칠 거리가 되는 것은 접지 않는다.**
- 중복된 버튼 묶음과 "시간" 창을 없앤다.
- PDF 저장 결과가 화면과 어긋나지 않게 한다.

### 비목표 (이번엔 안 함 / 후속)

- 리포트 **내용**(피드백 문구, 육각형 축, 측정 규칙)은 바꾸지 않는다. 백엔드·프롬프트 계약 그대로다.
- 위 요약 띠 안(시안 B)은 채택하지 않는다.
- 보관함 상세는 **별도 spec**(`2026-11-07-account-archive-layout-design.md`)에서 이 화면을 재사용한다. 이 spec이 먼저 끝나야 한다.

## 2. 데이터 · 계약 (있다면)

## 3. 접근 제어 / 제약

### 채택 배치 — 왼쪽 요약 레일 · 오른쪽 문항

```
┌──────────────┬───────────────────────────────────────────────┐
│ 면접 리포트    │  (따라오는 머리) Q4 · 갈등을 푼 경험  1:24  6/16│
│ 벤·16문항·38:12│ ┌───────────────────────────────────────────┐ │
│ 보관함에 남김  │ │ Q4  팀에서 갈등이 생겼을 때…        1:24  │ │
│ ──────────── │ │ 내 답변                      ┌─────────┐ │ │
│ 총평 ▾        │ │ …                            │ 육각형   │ │ │
│  잘한 것 Q1 Q2│ │ 피드백                        └─────────┘ │ │
│  고칠 것 Q2-1 │ │ …                                         │ │
│  전달력       │ │ 318 음절/분 · 쉼 잦음 · 첫마디 2.8초  펴기▾│ │
│  공고 적합도   │ └───────────────────────────────────────────┘ │
│ ──────────── │   │ 꼬리질문                                   │
│ 문항  읽음 7/16│   ┌─────────────────────────────────────────┐ │
│ ■ Q1 자기소개 │   │ Q4-1 그때 상대는 뭐라고…          0:49  │ │
│ ■ Q2 …  1:18 │   └─────────────────────────────────────────┘ │
│   └ Q2-1 …   │                                               │
│ □ Q4 …(현재)  │                                               │
│ ──────────── │                                               │
│ [복사][PDF][다시]│                                             │
└──────────────┴───────────────────────────────────────────────┘
     336px
```

- 레일은 **336px 고정**, 화면에 붙어 따라온다. 위에서부터 머리글 · 총평 · 문항 목차 · 액션 버튼.
- **액션 버튼은 레일에 한 번만** 둔다. 본문 위아래의 두 묶음을 없앤다.
- **"시간" 창을 없앤다.** 문항별 시간은 목차 줄 오른쪽에, 60초 초과 개수는 목차 머리에 한 줄로 적는다.
- 무료 리포트는 총평·측정값이 없다. 레일에 머리글 · 목차 · 액션만 둔다.

### 긴 리포트에서 더해지는 장치 넷

1. **목차만 따로 스크롤.** 16줄이 레일을 넘기면 목차 영역 안에서만 스크롤한다. 본문 스크롤과 분리된다. 그때 총평은 접어 목차에 자리를 내준다(`총평 ▾`).
2. **지금 문항이 위에 붙는다.** 번호 · 질문 · 시간 · `6 / 16`을 담은 얇은 줄이 본문 머리에 붙어 따라온다.
3. **꼬리질문은 들여쓰기.** 본질문 아래로 26px 들어가고 세로선 한 줄이 잇는다. 16개가 평평하게 늘어서는 대신 10덩이로 읽힌다.
4. **읽은 데까지 표시.** 지나간 문항은 네모가 채워지고 글자가 흐려진다. 목차 머리에 `읽음 7 / 16`.

- 현재 문항 하이라이트와 읽음 표시는 `IntersectionObserver`로 정한다. `scrollTop`을 읽지 않는다.

### 읽기 규칙 다섯

1. **한 줄은 `--read-w`(68ch)에서 끊는다.** 넓은 모니터에서 본문이 폭을 다 쓰면 줄 끝에서 다음 줄 머리를 못 찾는다. 남는 자리는 비워 둔다.
2. **여백이 경계를 만든다.** 카드 사이 `--gap-card`(32) > 카드 안쪽 둘레(20) > 답변·피드백 사이(14) > 라벨·본문 사이(5). 바깥이 안보다 넓어야 한 장으로 읽힌다.
3. **노랑은 카드마다 한 번.** 지금 `splitEmphasis`가 `**…**`를 전부 칠한다. 넷이 칠해지면 아무것도 강조되지 않는다. 가장 중요한 한 구절만 칠한다.
4. **색은 셋만.** 노랑=고칠 구절, 빨강=60초 초과, 초록=읽음·충족. 그 밖에는 쓰지 않는다.
5. **목차는 진짜 `<a href="#q4">`.** <kbd>Tab</kbd> 차례가 저절로 맞고 브라우저 뒤로 가기로 읽던 자리에 돌아온다. 이동은 **즉시**(부드러운 스크롤 금지 — 16문항 거리에서 멀미가 난다). 도착한 카드에 노란 테두리가 잠깐 켜지고, `prefers-reduced-motion`에서는 켜진 채로 둔다.

### 카드 속

- 질문이 **제목 줄**이 되고 시간이 그 줄 오른쪽에 붙는다 — "시간" 창이 사라지는 자리다.
- 라벨(`내 답변` · `피드백`)을 **본문 위**로 올려 본문이 폭을 다 쓰게 한다. 줄간 `--lh-read`(1.85).
- 벤 측정값은 규칙 하나로 정리한다 — **눈에 띄는 축은 근거까지 펼치고, 보통인 축은 이름만 한 줄로.** "자신감 낮음"만 보이고 근거가 접히면 고칠 수가 없으므로, 접는 것은 **보통으로 나온 축**뿐이다.
- 육각형 프로필은 카드 안에서 작게 두고, 누르면 축 목록까지 편다.

### 절대 접지 않는 것

- **내 답변 원문** — "내가 한 말을 그대로 보여 준다"가 이 화면의 존재 이유다.
- **피드백** — 고칠 점을 보러 온 사람에게 고칠 점을 숨기는 꼴이다.
- **눈에 띄는 축의 근거.**

### PDF 저장

- **접힌 것을 전부 펴서** 인쇄한다. 종이에는 펴기 버튼이 없다.
- 레일과 목차는 빼고 **총평 → 문항** 한 줄기가 된다. `@media print` 블록에 넣는다(인쇄용 색 토큰이 이미 있다).
- 육각형은 남긴다. 인쇄 토큰에서 `--line`이 검정이라 선만으로 읽힌다 — 채움색은 빼고 테두리만 그린다.

## 6. 무회귀 · 롤아웃

- 계약 변경이 없어 단독 배포 가능하다.
- **`ReportCards.vue`는 보관함 상세도 쓴다.** 이 spec의 카드 변경은 보관함에도 즉시 나타난다. 보관함 레이아웃 자체는 다음 spec에서 다루지만, 카드가 먼저 바뀌어도 깨지지 않아야 한다.
- 예전에 저장된 리포트에는 `profile`이 없다(`docs/API.md` 396행 주석). 그때는 기존 측정값 표를 그리는 현재 분기를 **그대로 유지**한다.
- "시간" 창을 없애면서 **`overBy`·`overCount` 계산을 잃지 않는다.** 목차 줄과 머리로 옮긴다.
- PDF 저장은 `window.print()` 경로 그대로다. 탭 제목을 잠깐 바꿨다 복원하는 현재 처리도 유지한다.
- 배포 순서: 작업 PR → `dev` → demomo에서 **무료 리포트와 벤 리포트를 모두** 확인(벤은 티켓 소모) → `dev → main`.

## 8. 성공 기준

- 문항 16개짜리 벤 리포트에서 목차를 눌러 **Q4-1로 한 번에** 갈 수 있고, 뒤로 가기로 읽던 자리에 돌아온다.
- 본문을 읽는 동안 위에 붙은 줄이 지금 문항 번호와 `n / 16`을 보여 준다.
- 액션 버튼 묶음이 화면에 **한 번만** 나온다.
- "시간"이라는 이름의 창이 없고, 60초 초과 문항이 목차에서 빨강으로 보인다.
- 1920px 창에서 본문 한 줄이 68자를 넘지 않는다.
- 벤 카드에서 보통으로 나온 축은 한 줄로 접히고, 낮음·있음으로 나온 축은 **근거까지 펼쳐진** 채다.
- PDF로 저장하면 레일이 없고, 화면에서 접혀 있던 축의 근거가 **전부 들어가** 있다.
- 예전에 저장한(프로필 없는) 벤 리포트를 보관함에서 열어도 깨지지 않는다.
- 프론트 게이트 전부 통과.
