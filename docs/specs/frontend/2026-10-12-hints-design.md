## 0. 배경

여러 사람이 써 보는 동안 같은 질문이 반복됐다.

> "어떤 버튼을 눌러야 하지?" · "어디를 보고 있어야 하지?" · "다음은 뭘 해야 넘어가지?"

화면은 넷(랜딩·준비·면접·리포트)이고 각 화면에서 할 일이 분명한데, **지금 무엇을 해야 하는지 말해 주는 곳이 없다.** 처음 온 사람이 따라갈 수 있어야 하고, 처음이라도 건너뛸 수 있어야 한다.

## 1. 접근 — 왜 오버레이 투어가 아닌가

| 안 | 내용 | 판정 |
|---|---|---|
| A. 단계 투어 | 요소를 하이라이트하며 "다음 →"으로 넘기는 오버레이 | ✗ |
| **B. 상황별 힌트** | **화면 아래 한 줄. 지금 상태에서 할 일 하나만 말한다** | **채택** |

A를 버린 이유: 이 서비스의 흐름은 **다운로드 진행률·모델 준비 여부에 따라 순서가 달라진다.** 재방문자는 동의·장비 확인을 건너뛰고, 다운로드가 느리면 준비 화면에 오래 머문다. 고정된 단계 투어는 그 순서를 못 따라가고, 투어를 보는 동안 정작 해야 할 일(이력서 올리기)을 못 한다.

B는 **상태를 보고 지금 할 일을 고른다.** 재방문자에게는 재방문자 몫만 뜨고, 다운로드 중에는 "기다리는 동안 할 일"을 말한다. 투어 상태 기계가 없으므로 흐름이 바뀌어도 따라간다.

## 2. 규칙

1. **한 번에 하나.** 조건을 만족하는 힌트가 여럿이면 우선순위 첫 번째 하나만 띄운다.
2. **한 줄.** 말풍선 한 줄, RPG 대화창 톤. 화면을 가리지 않는다.
3. **읽으면 끝.** `확인`을 누른 키는 다시 뜨지 않는다. 누르지 않고 지나가면 조건이 다시 성립할 때 또 뜬다 — 안 읽은 사람에게는 한 번 더가 맞다.
4. **닫으면 쉰다.** `확인` 직후 다음 힌트가 곧바로 튀어나오지 않는다. **상황이 바뀌어야** 다시 말을 건다. 안 그러면 닫을 때마다 다음 것이 올라와 잔소리가 된다.
5. **언제든 끄기.** `그만 보기`로 전부 끈다. 다시 켜는 길은 준비 화면 설정에 둔다.
6. **기억은 이 브라우저에.** 본 키와 켬/끔을 `localStorage`에 둔다. 서버로 보내지 않는다.

## 3. 힌트 8개

우선순위 순이다. 위에서부터 조건을 보고 처음 맞는 것 하나를 띄운다.

| 키 | 화면 | 조건 | 문구 |
|---|---|---|---|
| `pick-interviewer` | 랜딩 | 면접관 미선택 | 먼저 면접관을 고르세요. 고른 사람의 목소리로 면접이 진행됩니다. |
| `go-prepare` | 랜딩 | 항상 | 아래에서 다운로드에 동의하고 장비 확인을 마치면 준비 화면으로 넘어갑니다. |
| `prepare-profile` | 준비 | 직군·직무 미입력 | 모델을 받는 동안 직군과 희망 직무를 채워 주세요. 왼쪽 출근 장면이 다운로드 진행률입니다. |
| `prepare-resume` | 준비 | 직군·직무 입력됨, 이력서 없음 | 이력서 PDF를 올리거나 붙여 넣으세요. 파일은 이 브라우저를 떠나지 않습니다. |
| `prepare-start` | 준비 | 시작 가능 | 준비됐습니다. `면접 시작`을 누르면 면접관이 첫 질문을 합니다. |
| `interview-answer` | 면접 | 답할 차례, 아직 한 번도 답 안 함 | 면접관이 기다립니다. 아래 칸에 쓰거나 `말하기`로 목소리로 답하세요. |
| `interview-end` | 면접 | 한 번 이상 답함 | 그만하고 싶으면 `면접 끝내기`를 누르세요. 리포트는 그때 만들어집니다. |
| `report-read` | 리포트 | 항상 | 항목을 펼치면 근거가 된 답변이 보입니다. `PDF로 저장`으로 남길 수 있습니다. |

준비 화면에 셋을 둔 이유는 거기가 가장 오래 머무는 화면이고(5~15분) 할 일이 둘(프로필·이력서)이기 때문이다. 면접 화면은 둘로 줄였다 — 답하는 중에 말을 거는 것은 방해다.

## 4. 구조

| 파일 | 역할 |
|---|---|
| `utils/hints.ts` (신규) | `HINTS` 목록과 `hintFor(ctx)`. **순수 함수.** 조건이 전부 여기 모인다 |
| `stores/hints.ts` (신규) | 본 키 집합·켬끔, `localStorage` 읽기/쓰기 |
| `components/ui/HintBar.vue` (신규) | 화면 아래 말풍선 한 줄 + `확인`·`그만 보기` |
| `App.vue` | 각 화면 위에 `HintBar` 하나. 스토어에서 맥락을 모아 넘긴다 |

```ts
export interface HintContext {
  phase: Phase
  interviewerPicked: boolean
  profileDone: boolean
  resumeDone: boolean
  canStart: boolean
  /** 면접 단계 — 'waiting'일 때만 답할 차례 */
  stage: Stage
  answered: boolean
  seen: readonly string[]
  enabled: boolean
}
export function hintFor(ctx: HintContext): Hint | null
```

조건을 전부 `hintFor` 하나에 모으는 것이 이 설계의 핵심이다. 화면마다 `v-if`로 흩어 두면 "지금 왜 이게 떴지"를 추적할 수 없고, 둘이 동시에 뜨는 것을 막지 못한다. 순수 함수 하나면 표를 그대로 테스트한다.

`utils/`는 브라우저 API를 import하지 않는다는 영역 규칙을 지킨다 — `localStorage`는 스토어 몫이다.

맥락은 **전부 스토어에서 나온다.** 동의 여부는 `LandingView`의 지역 상태라 스토어에서 볼 수 없어, 그것을 끌어올리는 대신 `go-prepare`를 랜딩의 **기본 힌트**로 두었다. 면접관을 고른 사람에게도, 고르라는 말을 이미 읽은 사람에게도 다음 할 일은 같다.

`그만 보기`를 되돌리는 길은 준비 화면의 면접관 줄에 `도움말 다시 보기`로 둔다. 꺼져 있을 때만 보인다.

## 5. 테스트

- 8개 각각: 조건이 맞으면 그 키가 나온다
- 우선순위: 조건이 둘 이상 맞을 때 위의 것 하나만 나온다
- 본 키는 건너뛴다 — 다음 순위가 나온다
- 전부 봤으면 `null`
- `enabled: false`면 조건과 무관하게 항상 `null`
- 답하는 중(`stage !== 'waiting'`)에는 면접 힌트가 안 뜬다
- 스토어: `localStorage`가 막힌 브라우저에서도 던지지 않는다(`muted`와 같은 `try/catch`)
- 컴포넌트: `확인`이 키를 본 것으로 기록하고, `그만 보기`가 전부 끈다
- 컴포넌트: `확인` 뒤 상황이 그대로면 다음 힌트가 안 뜨고, 상황이 바뀌면 뜬다
- 준비 화면: 꺼 둔 사람에게만 `도움말 다시 보기`가 보이고, 누르면 본 기록도 비워진다

## 6. 제외

- 요소 하이라이트·화살표·오버레이
- "다시 보기" 전체 투어
- 힌트 문구의 다국어
