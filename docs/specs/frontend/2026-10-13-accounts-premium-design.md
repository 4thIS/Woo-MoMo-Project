## 0. 배경

지금까지는 등급이 없었다. 누구나 들어와 무료 면접관으로 면접을 보고, 리포트 화면을 벗어나면 전부 사라진다. 회의(2026-10-13)에서 **비로그인 / 로그인 / 모모 프리미엄** 세 등급과 보관함·프리미엄 면접관을 넣기로 했다.

프론트와 백엔드는 **독립적으로 진행한다.** 프론트는 API가 없는 동안에도 전 화면을 완성할 수 있어야 한다(8절).

## 1. 결정 사항

| 항목 | 결정 | 근거 |
|---|---|---|
| 데이터 위치 | **서버 저장**(SQLite). 로그인 사용자의 이력서·면접 기록·녹음이 서버로 간다 | 기기를 바꿔도 보관함이 보여야 한다 |
| 로그인 | 이메일 + 비밀번호, **구글 소셜** 병행. **이메일 인증 없음**, 중복 검사만 | 데모 범위. 가입 마찰 최소 |
| 대입/회사 페르소나 | **cw 영역.** 프론트는 면접관이 들고 있는 라벨만 그린다 | 프롬프트는 계층 규율 경로(`src/prompts/`)이고 소유자가 cw다 |
| 토스 결제 | 목업이지만 **결과는 진짜** — 결제를 마치면 프리미엄이 켜지고 티켓 10장이 들어온다 | 심사위원이 벤을 직접 써 봐야 한다 |

## 2. ⚠️ 개인정보 원칙이 바뀐다

루트 `CLAUDE.md`의 **절대 하지 말 것 8번** — "이력서 텍스트·대화 내용을 서버로 전송하는 코드 작성 금지" — 과 정면으로 어긋난다. 로그인 보관함은 그 전송을 전제로 한다.

이 설계는 원칙을 **버리지 않고 등급으로 가른다.**

| 등급 | 이력서 | 대화·리포트 | 비고 |
|---|---|---|---|
| 비로그인 | 기기에만 | 기기에만, 리포트를 벗어나면 소멸 | **지금 그대로.** 소개 문구 "기기를 떠나지 않습니다"가 계속 참이다 |
| 로그인 | 서버 | 서버 | 사용자가 **명시적으로 동의**하고 저장한다 |
| 프리미엄 | 서버 | 서버 + 음성 녹음 | 벤은 Claude API라 대화가 외부로도 나간다 |

**그래서 필요한 것 (이 spec의 선행 조건):**

1. `CLAUDE.md` 8번을 "**비로그인은** 기기를 떠나지 않는다. 로그인 사용자의 데이터는 동의를 받고 서버에 저장한다"로 개정 — 공동 영역이라 cw 승인 필요
2. 랜딩 소개 문구를 "이 컴퓨터 안에서"에서 비로그인 기준임이 드러나게 수정
3. **회원가입·로그인 화면에 저장 동의 문구**를 둔다. 무엇이 저장되는지(이력서 원문·대화 전문·리포트·프리미엄은 녹음까지) 적는다
4. 벤 선택 시 "이 면접은 외부 AI(Claude)로 진행되어 대화가 서버를 거칩니다"를 **면접 시작 전에** 알린다

3·4번은 선택이 아니다. 로컬 실행을 내세운 서비스가 조용히 서버로 보내면 그게 가장 큰 결함이다.

## 3. 면접관 4명

회의에서 이름과 역할이 정해졌다. **기존 스프라이트·목소리 자산을 그대로 쓴다** — 바뀌는 것은 이름·순서·등급뿐이다.

| 순서 | 이름 | 수식 | 기존 id | 분야 | 등급 | 엔진 |
|---|---|---|---|---|---|---|
| 1 | **데이빗** | 기본 면접관(남) | `m1` | 회사 | 무료 | 로컬 LLM |
| 2 | **쥴리** | 압박 면접관(여) | `f2` | 회사 | 무료 | 로컬 LLM |
| 3 | **올리비아** | 기본 면접관(여) | `f3` | 대입 | 무료 | 로컬 LLM |
| 4 | **벤** | 압박 면접관(남) | `m2` | 대입·회사 | **프리미엄** | **Claude API** |

- 카드 순서가 위 표의 순서다(지금은 `m1 · f3 · m2 · f2`라 바뀐다).
- 수식("기본"·"압박")은 그대로 두고 **세부 페르소나는 cw가 설계한다.** 프론트는 `interviewers/index.ts`에 이름·분야·등급 필드만 더한다.
- 기본 면접관(`DEFAULT_INTERVIEWER`)은 **데이빗**으로 바꾼다. 지금 기본값 `f3`(올리비아)는 대입 전용이 되어 회사 면접 기본값으로 맞지 않는다.

### 벤 카드

- 카드 **오른쪽 위에 프리미엄 배지** — 별 훈장 안에 `P`. PixelLab으로 제작(9절).
- 프리미엄이 아닌 상태에서 벤을 누르면 **기능 비교표 모달**이 뜬다(면접관이 선택되지 않는다).
- 프리미엄이면 평범하게 선택되고, 카드에 **남은 티켓 수**를 표시한다.

## 4. 등급별 기능

| | 비로그인 | 로그인 | 프리미엄 |
|---|---|---|---|
| 무료 면접관 3명(데이빗·쥴리·올리비아) | O | O | O |
| 프리미엄 면접관(벤) | — | — | **티켓 10회** |
| 면접 기록 저장 | — | O | O |
| 리포트 다시 보기 | 화면을 벗어나면 소멸 | 보관함에서 | 보관함에서 |
| 이력서 미리 작성 | — | 대입 3 + 회사 3 | 대입 3 + 회사 3 |
| 보관함 한도 | — | **5개** | 5개(**프리미엄 기록은 한도에서 제외**) |
| 내 목소리 녹음 | — | — | O (보관함에서 재생) |

**보관함 5개 규칙:** 최신 5개를 남긴다. 6번째 면접이 끝나면 **가장 오래된 하나가 사라진다**(사라지기 전 확인을 띄운다). 프리미엄 면접으로 만든 기록은 이 숫자에 들어가지 않는다.

**티켓:** 면접이 **시작될 때** 1장 차감한다(완주 여부와 무관). 0장이면 벤을 고를 때 결제 모달이 뜬다. 중간에 끊긴 면접은 환불하지 않는다 — 환불 로직은 데모 범위를 넘고, 차감 시점을 시작으로 두면 규칙이 한 줄로 끝난다.

## 5. 상단 바

`App.vue`에 전역으로 하나 둔다(`components/TopBar.vue`).

```
비로그인   [                                           로그인 ]
로그인     [ 모모 프리미엄                    보관함  내정보 ]
프리미엄   [ 모모 프리미엄 ★                  보관함  내정보 ]
```

- **보이는 곳:** 랜딩 · 준비 · **리포트**. **면접 화면에서는 숨긴다** — 면접 중에 보관함을 여는 일은 없고, 면접 화면은 `100vh` 꽉 찬 레이아웃이라 자리가 없다.
- 리포트 화면에서 보이는 이유: 면접이 끝난 직후가 가입 전환이 일어나는 자리다. 비로그인으로 리포트를 보던 사람이 **"로그인하면 이 리포트를 보관할 수 있습니다"**를 여기서 만난다.
- 왼쪽 `모모 프리미엄`, 오른쪽 `보관함`·`내정보`. 비로그인은 오른쪽 `로그인` 하나.
- 힌트 바(`HintBar`)와 같은 `fixed` 요소다. 상단 바는 위, 힌트 바는 아래라 겹치지 않는다.

## 6. 모달

### 6.0 공통 — `components/ui/PixelModal.vue` (신규)

모달이 다섯 개라 먼저 하나를 만든다. 지금 리포에는 모달 기반이 없다(면접 화면의 종료 확인만 `position: absolute`로 박혀 있다).

- **항상 화면 한가운데.** 뒤 배경은 어둡게 덮는다
- `Esc` · 바깥 클릭 · 닫기 버튼으로 닫힌다
- 열려 있는 동안 포커스를 가둔다, 뒤 페이지는 스크롤하지 않는다
- 내용이 길면 **모달 안에서** 스크롤한다(모달 자체는 화면을 넘지 않는다)
- 좁은 화면에서는 가로를 꽉 채우고 위아래 여백만 남긴다
- 한 번에 하나만 연다. 모달 안에서 다른 모달을 열면 **갈아 끼운다**(쌓지 않는다). 예: 보관함 → 기록 상세

### 6.1 로그인 / 회원가입

- 탭 둘(로그인 · 회원가입)을 한 모달 안에
- 이메일 + 비밀번호, **구글로 계속하기** 버튼
- 회원가입: 이메일 중복 검사(입력을 떠날 때), 비밀번호 확인, **저장 동의 문구**(2절)
- 실패 문구는 칸 바로 아래. "이메일 또는 비밀번호가 올바르지 않습니다"로 뭉친다(계정 존재 여부를 흘리지 않는다)

### 6.2 모모 프리미엄 (기능 비교표 + 결제)

- 4절 표를 세 칸(무료 · 로그인 · 프리미엄)으로 그린다. **지금 내 등급 칸을 강조**한다
- 아래에 `프리미엄 시작하기` → **토스 결제 목업**으로 전환
- 목업 결제: 토스 결제창을 흉내 낸 화면 + `결제하기`. 누르면 2초쯤 "처리 중" 뒤 성공 → **프리미엄 켜짐 + 티켓 10장**
- 성공 화면에 "실제 결제가 아닙니다 (데모)"를 명시한다. 흉내는 내되 속이지는 않는다
- 비로그인이 이 모달에서 결제를 누르면 **로그인 모달로 갈아 낀다**

### 6.3 내정보

- 위: 이메일 · 가입일 · 등급 · 남은 티켓
- 아래: **내 이력서** — `대입` / `회사` 탭, 각 **최대 3개**
  - 목록(제목 · 수정일) → 누르면 편집
  - 편집은 준비 화면의 "간단 이력서" 폼을 재사용한다. 두 벌을 만들지 않는다
  - 3개가 차면 `새로 만들기`가 잠기고 "하나를 지워야 합니다"를 보인다
- 준비 화면에서 **"저장한 이력서 불러오기"**로 이 목록을 쓴다 — 이력서를 미리 쓰는 값이 거기서 나온다
- 레이아웃 세부는 **시안을 보고 정한다**(회의록). 이 spec은 담을 내용과 한도만 고정한다

### 6.4 보관함

- 목록: 날짜 · 면접관 이름 · 분야/직무 · 점수 요약. 프리미엄 기록에는 **P 배지**
- 비었으면 "아직 보관된 면접이 없습니다"
- 5개가 찼으면 목록 위에 "가장 오래된 기록이 다음 면접에서 사라집니다"
- 항목을 누르면 **상세로 갈아 낀다**(같은 모달 안)

### 6.5 보관함 — 기록 상세

- **왼쪽 위에 뒤로가기**(← 보관함). 회의록에서 못 박은 자리다
- 리포트 화면과 같은 내용을 보여 준다 — **`ReportView`의 카드 부분을 떼어내 공용으로 쓴다.** 리포트를 두 벌 만들면 둘이 어긋난다
- 프리미엄 기록이면 **내 목소리 재생**(답변별 재생)
- `PDF로 저장` · `이 기록 삭제`

계층 규율은 그대로다. `utils/`는 순수 함수만, `services/`는 스토어를 모르고, 화면은 스토어만 본다.

**`src/prompts/`는 건드리지 않는다.** 페르소나는 cw 몫이고 계층 규율 경로다.

## 8. API 없이 먼저 만든다

`services/account.ts`가 **인터페이스 하나**를 내보내고, 구현을 둘 둔다.

```ts
export interface AccountApi {
  signUp(email: string, password: string): Promise<Session>
  signIn(email: string, password: string): Promise<Session>
  signInWithGoogle(): Promise<Session>
  signOut(): Promise<void>
  me(): Promise<Session | null>
  emailTaken(email: string): Promise<boolean>

  listResumes(): Promise<ResumeSlot[]>
  saveResume(draft: ResumeDraft): Promise<ResumeSlot>
  deleteResume(id: string): Promise<void>

  listArchive(): Promise<ArchiveEntry[]>
  getArchive(id: string): Promise<ArchiveDetail>
  saveArchive(draft: ArchiveDraft): Promise<ArchiveEntry>
  deleteArchive(id: string): Promise<void>

  purchasePremium(): Promise<Session> // 목업 결제 — 티켓 10장이 들어온 세션을 돌려준다
  spendTicket(): Promise<Session>

  uploadRecording(archiveId: string, clip: Blob): Promise<string>
}
```

- **`mockAccount`** — `localStorage` + 인메모리. 가짜 지연 300ms, 실패 시나리오도 켤 수 있다. **이것으로 전 화면을 완성하고 테스트한다**
- **`httpAccount`** — cw의 API가 나오면 `fetch`로 같은 인터페이스를 채운다. 화면 코드는 **한 줄도 바뀌지 않는다**
- 어느 쪽을 쓸지는 `VITE_ACCOUNT_API` 환경 변수로 고른다. 기본은 목업

이 경계 하나로 두 사람이 서로를 기다리지 않는다. 주고받는 형태는 짝 문서에 적는다.

- `stores/account.ts`: 로그인/로그아웃 상태 전이, 티켓 차감, 목업 실패 시 상태가 깨지지 않음
- `TopBar`: 등급별로 보이는 버튼이 다르다, 면접 화면에서 숨는다
- `PixelModal`: `Esc` · 바깥 클릭으로 닫힌다, 포커스가 갇힌다, 한 번에 하나만 열린다
- 면접관 카드: 비프리미엄이 벤을 누르면 **선택되지 않고** 비교표가 열린다
- 결제 목업: 성공하면 등급이 프리미엄이 되고 티켓이 10장이 된다
- 비로그인: 리포트를 벗어나면 기록이 남지 않는다(기존 동작이 깨지지 않는지)

전부 목업 구현으로 돈다. 서버 없이 CI에서 통과해야 한다.

## 11. 범위 밖 · cw에게 넘기는 것

**이 spec에 없는 것 (cw 영역):**

- 데이빗 · 쥴리 · 올리비아 · 벤의 세부 페르소나 문구와 리포트 말투 (`src/prompts/` — 계층 규율)
- 대입 면접이 **무엇을 더 물어야 하는지**(학교 · 학과 · 전형 같은 입력이 필요한지). 필요하면 프론트에 입력 칸을 더해야 하니 **정해지면 알려 주세요**
- 벤의 Claude API 연동 · RAG, 서버 측 프롬프트
- SQLite 스키마, 인증 구현, 구글 OAuth 앱 등록

**이번 프론트 범위가 아닌 것:**

- 비밀번호 찾기 · 이메일 인증 (회의에서 "인증 없이"로 정함)
- 실제 결제 (목업)
- 보관함 검색 · 정렬 · 내보내기
- 녹음 편집. 재생만 한다
