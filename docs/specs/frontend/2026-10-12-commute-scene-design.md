- 생성일시: 2026-10-12
- 수정일시: 2026-10-12
- 상태: 구현 완료
- 담당: @leemonta9482
- 상위 문서: `docs/superpowers/specs/2026-09-15-mock-interview-design.md`

## 0. 배경

모델을 받는 동안 준비 화면에서 주인공이 출근하는 장면을 보여 준다. 다운로드는 5~15분 걸리는데 구간이 넷(속옷 0% → 양복 30% → 가방 70% → 도착 100%)뿐이고 각 구간이 걷기 루프 하나라, 한 루프를 1~4분 본다.

## 1. 결정 사항

처음에는 **구간을 8개로 늘리고 고른 면접관이 64×64 전신으로 출근하는** 개편을 설계했다. 시안을 본 뒤 **계획을 바꿨다** — 새 전신 캐릭터의 품질이 기대 이하였고, 기존 캐릭터의 서사는 이미 통했다. 그래서 **서사와 캐릭터는 그대로 두고 애니메이션 품질만 올린다.**

| 항목 | 결정 |
|---|---|
| 서사 | 기존 4구간 유지 (속옷 → 양복 → 가방 → 도착) |
| 캐릭터 | 기존 캐릭터 유지. 기존 스프라이트를 **레퍼런스로 PixelLab에 다시 등록**해 생김새를 보존 |
| 해상도 | 32×32 → **44×44** |
| 걷기 | 7프레임 → **16프레임**. 다리 교차 단계가 촘촘해진다 |
| 줍기 | 9 → 12프레임. `pickup_suit`은 속옷에서 시작해 양복 차림으로 끝난다(`end_frame`) |
| 잔동작 | **`walk_watch`** 하나. 구간이 길 때 걸으며 시계를 본다 |
| 소품 | 지나가는 소품 **3종** — 고양이 · 자판기 · 비둘기 |
| 캔버스 | 320×64 유지 |

**제외:** 면접관이 주인공이 되는 연출, 실내 장면(침실·세면대·옷장), 배경 6종, 신호등 정지 연출. 화단·가로등·신호등 소품은 생성했으나 장면에 맞지 않아 뺐다(에셋은 `versions/`에 남아 있다).

## 2. 구간

| 진행률 | 걷기 | 1회 동작 | 잔동작 | 문구 |
|---|---|---|---|---|
| 0% | `walk_underwear` | | | 출근 준비 중… |
| 30% | `walk_suit` | `pickup_suit` | `walk_watch` | 양복은 챙겼습니다. 가방을 찾는 중… |
| 70% | `walk_suit_bag` | `pickup_bag` | `walk_watch` | 가방도 챙겼습니다. 회사가 보이기 시작했어요. |
| 100% | (정지) | `look_up` | | 회사 앞입니다 |

구간 전환은 땅에 놓인 물건(`suit_ground`·`bag_ground`)이 캐릭터에 닿을 때 일어난다. 다만 **물건이 닿지 못해도 진행률이 가리키는 구간까지는 간다**(`stepScene`의 안전망). 이것이 없으면 느린 다운로드에서 물건이 화면 밖 수천 px 앞에 생겨 영원히 안 닿고, 끝까지 속옷 차림으로 걷는다 — 실제로 겪은 버그다. 물건 생성 거리는 `MAX_AHEAD = 640`으로 묶는다.

## 3. 잔동작과 소품

한 구간이 1~4분이라 같은 걷기만 보게 된다.

- **잔동작**: 15~25초 간격으로 `walk_watch`가 끼어든다. 1회 재생하고 걷기로 돌아간다. 줍기 전환 중이거나 도착한 뒤에는 끼어들지 않는다.
- **소품**: 걷는 동안 3~7초 간격으로 화면 오른쪽에서 생겨 왼쪽으로 흐른다. 배경 다음·물건 앞에 그린다.

## 4. 에셋

`pixminimax` 모드로 생성한다(`v3`는 품질이 나빴다). 동작마다 캔버스가 제각각(44×44·40×44·32×48)으로 나오므로 **44×44 공통 캔버스에 발바닥 y=42로 재배치**한다(`commute_normalize.py`). 그러지 않으면 장면에서 캐릭터가 커졌다 작아졌다 한다.

경로는 기존과 같은 `frontend/public/sprites/`이며 `manifest.json`이 프레임 수와 크기를 담는다. 파일이 없으면 기존 세트로 대체한다.

## 5. 픽셀 품질

`frontend/scripts/sprites/check.py`가 모든 시트를 검사한다. 걸리면 seed를 바꿔 다시 뽑는다.

| 검사 | 기준 |
|---|---|
| 고립 픽셀 | 사방이 투명한 1px 점 — 0개 |
| 캐릭터 흔들림 | 걷기 6px · 그 외 14px 이내. **같은 엣지끼리** 비교한다(네 엣지를 한데 모으면 이동량이 아니라 폭이 나온다) |
| 팔레트 이탈 | **인접 프레임끼리** 비교. 첫 프레임 기준이면 의도된 복장 변화까지 잡힌다. `pickup_`은 복장이 바뀌는 게 정의라 건너뛴다 |

생성한 모든 판은 리포 밖 `versions/`에 `index.json`(동작·프레임 수·seed·지시문)과 함께 보관한다.

## 6. 구조

| 파일 | 역할 |
|---|---|
| `utils/progressStages.ts` | 구간 정의, 물건 접근과 구간 전환(`stepScene`), 잔동작 스케줄(`nextIdleAt`·`pickIdle`), 소품 스폰·이동(`spawnProp`·`stepProps`). **전부 순수 함수** |
| `components/ui/PixelProgress.vue` | 캔버스, 시트 로드, 프레임 루프. 로직은 위에서 받아 쓴다 |
| `scripts/sprites/check.py` | 에셋 품질 검사 |

## 7. 테스트

- 5분·15분 두 속도로 전 구간을 흘려 모든 구간을 빠짐없이 지나는지
- 물건이 닿지 않아도 진행률을 따라가는지(안전망)
- 잔동작이 간격 안에서 나오고 줍기 전환과 겹치지 않는지
- 소품이 화면 밖으로 나가면 사라지는지, 한 틱에 화면 너비 이상 움직이지 않는지
- 진행률이 뒤로 가거나 크게 점프해도 구간이 망가지지 않는지

장면 로직이 순수 함수이므로 캔버스 없이 전부 테스트한다. 직전에 고친 "속옷 차림으로만 걷던" 문제가 그 테스트 부재에서 나왔다. 실제 화면은 `docs/demo-checklist.md`의 수동 시나리오로 확인한다.
