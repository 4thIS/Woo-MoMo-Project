## 0. 배경 · 위치

네 화면(랜딩·준비·면접·리포트)을 한 사람이 며칠 안에 만들어야 한다. 화면마다 색·글꼴·간격을 새로 정하면 톤이 흩어지고 시간이 샌다. 이 문서는 랜딩 시안에서 확정한 방향 C(게임 타이틀 + RPG 메시지 창)의 시각 언어를 **토큰과 컴포넌트 규칙**으로 고정해, 이후 모든 화면 spec이 이 문서를 참조만 하게 한다.

세계관 한 줄: **"면접관 AI가 이 컴퓨터 안에서 출근해 여러분을 기다린다."** 픽셀 캐릭터가 출근하는 다운로드 바(`pixel-progress`)와 RPG 메시지 창이 이 세계관을 시각으로 잇는다.

## 1. 목표 · 비목표

### 목표
- 색·글꼴·간격·테두리·모션의 단일 토큰 세트를 정의하고 CSS 변수 이름까지 고정한다.
- 재사용 컴포넌트(창, 태그, 선택 메뉴, 버튼, 스탯 카드, 진행 바, 스프라이트)의 모양과 상태를 정의한다.
- 네 화면이 각각 어떤 컴포넌트로 조립되는지 매핑해, 화면 spec에서 디자인 논의를 반복하지 않게 한다.
- 픽셀 그래픽의 기술 규칙(정수 배율, 스프라이트 시트 형식, 렌더링 속성)을 고정한다.

### 비목표 (이번엔 안 함 / 후속)
- 모바일·태블릿 대응. 실행 환경은 WebGPU Chrome 데스크톱(전체 설계서 제약)이다.
- 라이트 테마. 다크 단일 테마.
- 리포트용 정지 컷 등 추가 도트 그래픽. (면접관 3인·지원자 정수리는 제작 완료, 5절 참조.)
- 컴포넌트 라이브러리 도입. 전부 자체 CSS(전역 토큰 + 컴포넌트별 scoped 스타일).

## 2. 데이터 · 계약

없음. `backend/data/manifest.json` · `/api` 응답 스키마 변경 없음.

## 3. 디자인 토큰

구현 위치: `frontend/src/styles/tokens.css` (`:root` CSS 변수). 컴포넌트는 이 변수만 쓰고 색 리터럴을 쓰지 않는다.

### 3.1 색

| 변수 | 값 | 용도 |
|---|---|---|
| `--bg` | `#12142e` | 페이지 배경, 별하늘, 창 안의 오목한 영역(입력·표) |
| `--win` | `#1b1f4a` | 메시지 창 바탕 |
| `--raise` | `#2d3380` | 선택된 항목 배경, 로고 그림자, 아바타 틀 |
| `--line` | `#f2f2f2` | 창 테두리, 본문 텍스트 |
| `--text` | `#f2f2f2` | 본문 |
| `--text-2` | `#c9cdf5` | 보조 설명 |
| `--text-3` | `#7d83c9` | 라벨·메타·비활성 선택지. **13px 이하 본문에는 쓰지 않는다**(대비 약 4:1) |
| `--accent` | `#ffd23f` | 커서, 선택된 선택지 글자, 강조 단어, 진행 바 채움 |
| `--ok` | `#7ee081` | 통과·완료 |
| `--danger` | `#f26d6d` | 오류(WebGPU 없음, 다운로드 실패, 초기화 실패) |

- 배경 위 별: `radial-gradient(circle, #cfd3ff 1.5px, transparent 1.5px)` 140px 격자 + `#7d83c9` 90px 격자(45px, 60px 오프셋). 페이지 최상위 한 곳에만.
- 색은 이 10개로 끝낸다. 그라데이션은 별하늘 점 외에 쓰지 않는다. 반투명(`rgba`)도 쓰지 않는다 — 픽셀 세계관에 흐림이 없다.

세 벌 모두 Galmuri(OFL). 파일은 `frontend/public/fonts/`에 두고 `LICENSE.txt`를 함께 배포한다. Google Fonts에 없으므로 `@font-face` self-host.

| 변수 | 파일 | 역할 |
|---|---|---|
| `--font-display` | `Galmuri11-Bold.woff2` | 로고, 창 제목, 카드 제목, 버튼 |
| `--font-body` | `Galmuri14.woff2` | 본문, 대화, 선택지 |
| `--font-mono` | `GalmuriMono11.woff2` | 라벨, 수치, 파일명, 시스템 메시지 |

폴백 스택: `'Galmuri14', 'DotGothic16', sans-serif` / mono는 `'GalmuriMono11', monospace`. `-webkit-font-smoothing: none` 전역.

**타입 스케일** (픽셀 글꼴이라 기준 크기의 정수배에서 가장 또렷하다. 제목·라벨은 배수 고정, 본문은 가독성 우선으로 예외 허용)

| 토큰 | 크기 / 행간 | 글꼴 | 쓰는 곳 |
|---|---|---|---|
| `--fs-logo` | 154px / 0.95 | display | 랜딩 로고만 (11×14) |
| `--fs-h1` | 33px / 1.3 | display | 화면 대제목 (11×3) |
| `--fs-h2` | 22px / 1.4 | display | 창 제목, 카드 제목 (11×2) |
| `--fs-body-lg` | 24px / 1.6 | body | 면접관 말풍선(면접 화면) |
| `--fs-body-md` | 20px / 1.75 | body | 면접관 대사(랜딩 소개), 리포트 피드백 |
| `--fs-body` | 16px / 1.7 | body | 일반 본문, 선택지 |
| `--fs-body-sm` | 15px / 1.7 | body | 카드 설명 |
| `--fs-label` | 14px / 1.6 | mono | 표 라벨·값 |
| `--fs-meta` | 13px / 1.5 | mono | 안내 문구, 파일명, 힌트 (`--text-3` 금지, `--text-2` 이상) |

### 3.3 간격 · 크기

4px 격자. `--sp-1: 4px` `--sp-2: 8px` `--sp-3: 12px` `--sp-4: 16px` `--sp-5: 20px` `--sp-6: 24px` `--sp-8: 32px` `--sp-10: 40px` `--sp-14: 56px`.

- 페이지 좌우 여백 120px, 콘텐츠 최대 폭 **1040px** 중앙 정렬(`--content-w`). 창은 이 폭을 꽉 채운다.
- 창 안쪽 패딩 `32px 40px`. 창 사이 세로 간격 40px. 섹션 사이 60px.
- 히트 타깃 최소 44px 높이(버튼·선택지·체크).
- 모서리 반경 **0**. 예외 없음.

### 3.4 테두리 · 그림자

| 이름 | 값 |
|---|---|
| 창 테두리 | `border: 4px solid var(--line); box-shadow: inset 0 0 0 3px var(--win), inset 0 0 0 5px var(--line);` (바깥 4px 흰선 → 3px 바탕 → 2px 흰선) |
| 얇은 구분 | `2px solid var(--raise)` |
| 로고 그림자 | `text-shadow: 8px 8px 0 var(--raise)` |
| 포커스 링 | `outline: 2px solid var(--accent); outline-offset: 2px` |

블러 그림자(`box-shadow` blur > 0) 금지. 그림자는 항상 하드 오프셋.

### 3.5 모션

원칙: **프레임이 보이는 움직임**. 이징 곡선 대신 `steps()`. 예외는 스크롤 연동 페이드(선형)뿐.

| 토큰/이름 | 값 | 용도 |
|---|---|---|
| 스프라이트 걷기 | `0.8s steps(8) infinite` (10fps) | 프로그레스 캐릭터 |
| 바닥 스크롤 | `1.2s linear infinite`, 96px 주기 | 프로그레스 바닥 |
| 깜빡임 | `0.9s steps(1) infinite` (50% 듀티) | 커서, "▶ 시작" 안내 |
| 창 등장 | `transform: scale(.9→1)` `150ms steps(3)` + 즉시 불투명 | 창이 펼쳐질 때 |
| 타이핑 | 글자당 30ms, 문장부호 뒤 120ms 추가 정지 | 면접관 대사(랜딩 소개, 말풍선) |
| 스크롤 페이드 | 히어로 진행률 0→1에 따라 `opacity 1→0`, `translateY 0→-40px`, 선형 | 랜딩 로고 창 |
| 포커스 이동 스크롤 | `scrollIntoView({behavior:'smooth', block:'start'})` | 동의 → 장비 확인 |

`prefers-reduced-motion: reduce`이면 깜빡임·타이핑·창 등장을 끄고(최종 상태 즉시 표시) 걷기는 정지 프레임(0번) 유지. 스크롤 페이드는 유지(사용자가 스크롤을 직접 제어).

### 아이콘
인라인 SVG만. 이모지·딩뱃 문자(▶ ✓ ★ 등) 금지 — 글꼴에 따라 모양이 바뀌고 픽셀 톤이 깨진다. 스타일: 채움형, 사각 격자 기반, 16·20·24px. 필요한 것: 커서 삼각형, 체크, 아래 화살표, 마이크, 복사, 다시 시작. `frontend/src/components/ui/icons/`에 하나씩 `.vue`.

## 5. 픽셀 그래픽 규칙

- 모든 래스터 이미지는 `image-rendering: pixelated` + **정수 배율만**(×2·×3·×4). 소수 배율은 번진다.
- 스프라이트 시트: 가로 한 줄, 프레임 정사각. `manifest.json` 형식은 `pixel-progress/sheets/manifest.json` 그대로 (`{name: {file, frames, w, h}}`). 프론트는 이 JSON을 읽어 배치한다.
- 위치는 정수 px. `transform`으로 움직일 때도 정수로 반올림.
- 기존 에셋(`pixel-progress/sheets/`): 캐릭터 32×32(걷기 9프레임=0번 정지+8 루프, 줍기 9, 올려다보기 7), 회사 48×64, 바닥 아이템 20×20·16×16. 화면에서 캐릭터 ×4(128px), 회사 ×3(144px).
- 면접 에셋(`pixel-progress/interviewers/sheets/` + `manifest.json`, 제작 완료 2026-09-15): 면접관 3인 32×32, 정면, 얼굴은 그림자, 연한 회청색 양복, 세 명 모두 같은 49색 팔레트. 0번 프레임 = 기본 자세, 1~N 루프, 10fps.
  - left(여, 왼쪽): idle(5) · react(9) · watch(9) — nod 는 미사용, 듣기 상태도 idle
  - center(가운데, 발화자): idle(5) · talk(7) · nod(5) · react(9) · watch(9)
  - clerk(서기, 오른쪽): idle(5) · write(9)
  - candidate_back(지원자 정수리, 48×32, 정지 1장)
  - 상태 → 애니: 대기 idle/idle/idle · 질문 중 idle/talk/idle · 답변 듣는 중 idle/nod/write · 좋은 답변 react/react/write(1회) · 답변 지연 watch/watch/idle(1회)
  - 면접 화면 배율: 면접관 ×6(192px), 지원자 ×6(288×192)
- 면접실 배경은 CSS 색면(벽 `--win`, 윗띠·바닥 `--bg`, 걸레받이·책상 상판 `--raise`, 책상 앞면 `--win` + `--bg` 4px 윤곽). 이미지 아님. 별하늘은 랜딩·준비·리포트에만.

## 6. 문구 · 톤

- 면접관은 1인칭 존댓말("저는 … 준비합니다"). 세계관 문구는 면접관 대사 창에서만.
- 시스템 안내(mono `--text-2`)는 3인칭 중립 서술("선택하면 아래 창으로 이동합니다").
- **동의·면책·오류 문구는 장난기 없이** 사실만 적는다. RPG 톤은 창 모양과 선택 커서까지, 문장은 평범하게.
- 실행 시 채워지는 값은 시안에서 `[대괄호]`로 표시. 실제 화면에 대괄호가 남으면 버그.

## 7. 화면별 적용

| 화면 | 구성 |
|---|---|
| **LandingView** | 별하늘 배경 위 (1) 타이틀 `PixelWindow`(로고 154px + `PixelTag` "브라우저에서 실행 · 서버 전송 없음" + 한 줄 부제) + 깜빡이는 "▶ 아래로 내려서 시작" → 스크롤 페이드. (2) 면접관 소개 창: `Avatar` + `PixelTag`"면접관" + `SpeechText`(타이핑). (3) 동의 창: `KeyValueGrid`(모델·용량·저장 위치·삭제) + `ChoiceMenu` 2항목. ## 8. 접근 제어 / 제약

- 지원 환경: WebGPU 지원 Chrome 데스크톱. 뷰포트 최소 1024px 가정, 1024–1280 구간에서는 좌우 여백을 40px까지 줄이고 콘텐츠 폭 유지.
- 키보드만으로 전 흐름 진행 가능해야 한다(`ChoiceMenu` 화살표, 버튼 Tab/Enter, 포커스 링 항상 표시).
- 색 대비: 본문 조합(`--text`/`--text-2` on `--win`·`--bg`)은 7:1 이상. `--text-3`는 라벨·비활성 전용.
- 모델 출력은 `SpeechText`에서 텍스트 바인딩만(`innerHTML` 금지 — `frontend/CLAUDE.md`).

## 9. 영역별 영향

- frontend: `src/styles/tokens.css`, `src/styles/base.css`(reset·글꼴·별하늘), `src/components/ui/*`, `public/fonts/*` 신규. 화면 spec/plan은 이 문서를 참조.
- backend: 없음.
- deploy: 없음(글꼴은 정적 파일로 빌드에 포함, nginx 추가 설정 불필요).
- finetune: 없음.

## 10. 성공 기준

- `tokens.css` 외에 색 리터럴(`#…`, `rgb(`)이 `src/` 안에 없다(ESLint/grep 게이트).
- 네 화면 어디서 캡처해도 이 문서의 색 10개·글꼴 3벌·반경 0·하드 그림자 규칙 밖의 요소가 없다.
- `prefers-reduced-motion` 켠 상태에서 깜빡임·타이핑이 사라지고 흐름은 동일하게 완주된다.
- 키보드만으로 랜딩→리포트 완주.
- 랜딩 구현 결과가 시안 C와 나란히 놓였을 때 색·간격·글꼴 크기가 눈으로 구분되지 않는다.

## 11. 열린 결정 (plan 단계 또는 제작 시 확정)

- 면접관 스프라이트 프레임 크기(48×48 권장)와 면접실 배경 해상도 — 도트 제작 시 확정.
- 로고 154px이 1024px 뷰포트에서 두 줄 폭을 넘는지 — 넘으면 `clamp()`로 121px(11×11)까지 축소 허용.
- 타이핑 효과를 스트리밍 응답에도 적용할지(토큰 도착 속도가 이미 타이핑처럼 보이므로 불필요할 가능성 높음) — 면접 화면 spec에서 결정.
- 별하늘을 랜딩 외 화면에도 깔지, 면접 화면은 면접실 배경만 쓸지 — 면접 화면 spec에서 결정.
