# 데모 리허설 체크리스트 (수동)

> 자동 테스트로 못 잡는 항목만. 각 항목은 데스크톱 Chrome 최신, 실제 모델(E4B)로 확인한다.
> 2026-09-18 갱신: 모델·TTS는 브라우저가 Hugging Face에서 직접 받는다(`docs/specs/backend/2026-09-17-model-hosting-hf-design.md`). 로컬 8765 서빙은 더 이상 필요 없다.

## 면접 흐름

- [ ] 랜딩 → 동의 → 장비 확인 → 내려받기 → 준비 → 면접 시작 → 5문항 완주 → "면접이 끝났습니다" 창 → 리포트 받기
- [ ] 동의 창: 표(모델·용량·저장 위치·삭제)에 두 행(Gemma / supertonic-3·목소리 M2), 값은 매니페스트 기준. Gemma 체크박스는 체크 고정(비활성), 목소리는 기본 체크이고 해제 가능. 합계와 장비 확인의 "필요" 용량이 체크한 모델만 더한 값이다 (#27·#32·#36)
- [ ] 목소리 해제: 합계·필요 용량이 모델만, 준비 화면에 목소리 단계·"목소리 준비" 항목 없음, 면접은 텍스트 전용(음소거 토글·AI 합성 문구 없음). 선택이 새로고침 뒤에도 유지되고, 이미 받아 둔 TTS 캐시는 지워지지 않는다 (#36)
- [ ] 첫 방문(사이트 데이터 삭제 후): 준비 화면에서 모델과 목소리를 다 받은 뒤에만 회사 앞에 도착한다. 양복·가방·회사가 바닥 점선과 같은 속도로 흐르고 뚝뚝 점프하지 않는다 (#25·#26)
- [ ] 준비 창 제목이 단계를 따른다: 출근하는 중 → 잠깐 숨 고르는 중(초기화) → 목소리를 가다듬는 중 → 자리에 앉았습니다. 아래 문구와 모순되지 않는다 (#24)
- [ ] 재방문(새로고침): 랜딩 동의 창이 제목 "이미 받아 둔 모델", `✓ gemma4-e4b-it · supertonic-3 — 이 브라우저에 저장됨`으로 접히고(`자세히`로 표 펼침), 장비 확인이 자동 실행돼 한 줄로 접힌 뒤 `바로 준비하기` 버튼 하나로 준비 화면에 간다. 모델·목소리를 다시 받지 않고 초기화만 하며, 진행 장면은 0%부터 다시 걸어오지 않고 도착 상태(합산 100%)로 시작한다. Cache storage `momo-models`에 현재 매니페스트 항목(모델 1 + TTS 7)만 있다 (#30·#33)
- [ ] 재방문인데 디스크가 부족해도(이미 받아 둔 파일) 막지 않는다(필요 용량 0). 목소리를 켠 상태에서 TTS 항목만 지우면 재방문으로 보지 않고 첫 방문 흐름이다. 목소리를 해제한 사람은 Gemma만 있어도 재방문이다 (#33·#36)
- [ ] 면접 중 상단 시계가 1초마다 오른다. 질문 번호·남은 수는 어디에도 없다
- [ ] 면접관 고르기(랜딩 두 번째 창): 카드 3장. 첫 방문은 고르기 전 동의 선택지가 비활성이고 "면접관을 먼저 골라 주세요"가 나온다. 카드를 누르면 강조되면서 그 목소리가 바로 나온다(면접 음소거를 켜 둬도 나온다). 같은 카드를 다시 누르면 처음부터, 다른 카드를 누르면 앞 소리가 멈춘다
- [ ] 첫 방문 다운로드: Network에 목소리 JSON이 **고른 면접관 것 1개만** 받아진다(`voice_styles/{ID}.json`)
- [ ] 준비 화면 "바꾸기"로 다른 면접관을 고르면 약 290KB만 받고(Gemma 재초기화 없음) 첫 질문이 새 목소리로 나온다
- [ ] 재방문(목소리만 캐시에 없음): 진행 장면이 100% 미만에서 시작해 목소리 수신과 함께 도착한다. 기능 배포 전 사용자(선택 저장값 없음)는 기본 면접관이 선택된 채 "바로 준비하기" 한 번이다
- [ ] 면접관 3명 각각 1회 완주: 온화한 선배는 꼬리질문이 적고 반응이 부드럽다, 압박 면접관은 근거·수치를 캐묻는다. 리포트가 카드로 나오고(원문 카드 아님) 말투가 면접관을 따른다. 무대 가운데·상단 태그·리포트 헤더가 고른 면접관이다

## 말하기

- [ ] 말하기 켜고 한 문장 말한 뒤 입을 다물면 카운트다운 바가 보이고 3초 뒤 자동 전송·생성 시작
- [ ] 말하기 켜고 아무 말 안 하면 보내지지 않는다 (인식기가 스스로 꺼져도)
- [ ] 말하는 도중에는 바가 계속 리셋되어 보내지지 않는다. 토글을 끄면 취소되고 텍스트는 남는다

## 음성(TTS) — 이슈 #12 단독 확인 (dev 콘솔)

- [ ] 로컬: 백엔드(`cd backend && uv run uvicorn app.main:app`)와 `pnpm dev`를 켠 상태에서 콘솔. TTS 파일은 매니페스트의 HF 주소에서 받으므로 로컬 모델 서빙은 필요 없다:
      `const m = await __momoTts.getManifest(); await __momoTts.initTts(m.tts, (r,t)=>console.log(r,t)); const c = await __momoTts.synthesize('안녕하세요. 자기소개를 부탁드립니다.'); __momoTts.warmUpAudio(); __momoTts.playClip(c, {muted:false})`
- [ ] 60자 한국어 문장 합성 시간 3초 이내(스텝 4, 첫 호출은 워밍업 제외). 합성 중 면접실 애니가 멈추지 않는다
- [ ] DevTools Network: 외부 요청은 모델·TTS 파일(`huggingface.co` → `*.hf.co` 리다이렉트)뿐이고, ORT 런타임은 같은 오리진 `/ort-wasm/…jsep.{mjs,wasm}`. `.mjs`의 Content-Type이 `text/javascript`. 이력서·대화가 실린 요청은 없다. 두 번째 방문은 모델·TTS 요청 없이 캐시에서

## 음성(TTS) — 면접 연동 (이슈 #13)

- [ ] 준비 화면: 진행률은 모델+TTS 합산 한 줄로 0→100% 한 번만 오른다(목소리 단계에서 0%로 돌아가지 않음). 모델 초기화 동안은 약 88%에서 잠시 멈추고, TTS까지 다 받은 뒤 회사 앞에 도착(look_up)한다. 체크리스트에 "목소리 준비" 줄이 있고, 둘 다 완료돼야 `면접 시작`이 열린다
- [ ] 첫 질문: 말풍선이 "…"로 있다가 음성이 나오기 시작하면서 글자가 말 속도에 맞춰 드러난다(끝나는 시점이 음성과 같다). 가운데 면접관은 말하는 동안 질문 제스처를 반복
- [ ] 재생 중 말하기·전송·텍스트 영역이 잠기고, 답변 타이머는 없다가 재생이 끝나면 60초에서 시작한다
- [ ] 우상단 스피커 토글: 재생 도중 눌러도 즉시 조용해지고(글자는 계속 드러남), 새로고침해도 상태가 남는다
- [ ] 재생 중 `면접 종료 → 리포트 만들기`: 소리가 바로 멈추고 리포트로 넘어간다. 리포트 응답은 읽지 않는다
- [ ] (Gemma 캐시 히트, TTS 캐시 없음 상태에서 — Application → Cache storage에서 `supertonic-3` 항목만 삭제) DevTools Network → 우클릭 "Block request domain"으로 `huggingface.co`를 막고 준비: "목소리를 준비하지 못했습니다: …"와 `다시 시도`(TTS만). 차단을 풀고 다시 시도하면 Gemma 재초기화 없이 목소리만 준비된다
- [ ] 60자 질문의 "생각 중"(생성+합성) 첫 턴 8초 이내, 이후 6초 이내 — 측정값을 PR에 적는다
